# 개발 프롬프트 — 교안 출력물을 「시판 대학 참고서급 교재 디자인」으로 업그레이드

> 사용법: 새 계정의 Claude 세션에 **이 파일 + 교안변환기_인수인계.md + kyoan-conv-handoff.zip** 을 첨부하고, 아래 「프롬프트 본문」을 그대로 붙여 넣으세요.
> Vercel 커넥터는 기존과 같은 Vercel 계정(팀 `yjparks-projects-18926ad8`)으로 연결되어 있어야 합니다.

## 프롬프트 본문

너는 **출판 편집 디자이너(InDesign 조판 경력)** 이면서 **프런트엔드 개발자**다.
첨부한 인수인계 문서(교안변환기_인수인계.md)와 소스 번들(kyoan-conv-handoff.zip)을 먼저 끝까지 읽고, 운영 중인 「교안 HTML 변환기」에 **교재 디자인 출력 모드**를 추가해라.

### 0. 목표

지금 변환기는 교안 PDF의 각 페이지를 **이미지로 그대로** 플립북에 담는다. 이것을 **시판 중인 대학 참고서(전공 교재) 수준의 편집 디자인**으로 다시 조판한 결과물을 만들 수 있게 업그레이드한다.

- 책 전체에 통일된 **디자인 시스템**(판형·그리드·타이포그래피·색·요소)이 적용될 것
- **챕터마다** 별도의 챕터 표지(도비라)와 챕터 고유 색이 적용될 것
- **페이지마다** 내용 유형에 맞는 레이아웃 템플릿이 자동 적용될 것
- 본문 요소(제목 계층, 핵심 개념 박스, 예제, 팁, 주의, 표, 그림·캡션, 요약, 확인 문제, 용어 정의 등)가 **각각 디자인된 컴포넌트**로 표현될 것
- 결과물은 **InDesign으로 조판한 책처럼** 보여야 한다. "웹페이지 같은" 결과는 불합격

기존의 「원본 그대로(이미지)」 방식은 그대로 두고, 출력 형식에 **「교재 디자인」** 을 새 선택지로 추가한다.

### 1. 현재 시스템에서 반드시 알아야 할 것 (인수인계 문서 요약)

- 변환기 = Vercel 프로젝트 `kyoan-conv` (who-ebook.vercel.app), 교안 열람 사이트 = `who-ebook` (ebook.whomedia.co.kr). GitHub 없음, Vercel 무료 플랜
- `index.html` 은 로더다. `p/00~21.txt`(+`fx1.txt`)를 이어 붙여 `Ɛ→\`, `Ƒ→"`, `ƒ→줄바꿈` 으로 복원하고 `ƓƓSECTIONƓƓ` 로 [화면 HTML / 숨김 템플릿 / 앱 JS] 3덩어리로 나눈다. 원본 조각은 수정하지 말고 **로더의 `t.replace` 와 별도 모듈 파일**로 기능을 덧붙이는 방식을 유지할 것
- 번들의 `decode_app.py` 로 `app.txt` 를 만들어 원본 앱 구조를 먼저 분석할 것
- 변환 결과 데이터(`deck`) 구조 (분석으로 확인할 것):
  - `deck.pages[]` = `{ t:'img', src:'p0', w, h, text:[[문자열, left%, top%, 글자크기(cqw), scaleX], …], links:[…] }`
  - `deck.media` = `{ p0: dataURL, … }` (페이지 렌더 이미지)
  - `deck.outline` = PDF 책갈피 `[{ t:제목, p:페이지, d:깊이 }]`
  - PDF 텍스트는 pdf.js `getTextContent()` 로 추출되며 transform에서 글자 크기를 계산하고 있음 → 제목 추정에 활용 가능
  - 출력 HTML은 `kind`(flip/plain) 설정에 따라 생성되며, 뷰어는 숨김 템플릿 `#v-css / #v-js / #v-body` 를 사용
- 저장 흐름(웹 저장 → 삭제 코드 → 작업 이력 IP 기록 → 30일 휴지통)은 그대로 재사용
- **배포 규칙**: Vercel MCP `create_deployment`. 바뀐 파일은 inline, 안 바뀐 파일은 `deploy-manifest.json` 의 sha 참조. 파일 안에 `\uXXXX` 문자열 금지(`\x` 사용). 배포 후 `curl … | sha1sum` 으로 반드시 대조
- 사용설명서(`manual.html`)는 기능이 바뀌면 **알아서 함께 갱신**. 비밀번호 노출 금지
- 문구는 **간결·정제체**("변환하여", "업로드하세요"), 디자인 톤은 현재 skin.css(SaaS, 남색 #3056D3)와 어울리게

### 2. 처리 파이프라인 (설계 기준)

```
PDF ─▶ ① 추출 ─▶ ② 구조화(블록 모델 JSON) ─▶ ③ 교정 편집기 ─▶ ④ 조판 엔진(테마·템플릿)
     ─▶ ⑤ 페이지 분할(판형 기준) ─▶ ⑥ 출력: 플립북 HTML(텍스트 선택·검색 가능) + 인쇄용 PDF
```

**① 추출**
- pdf.js `getTextContent()` 로 글자·위치·크기·폰트명(굵기 추정)을 수집하고, 줄 → 문단으로 병합
- 그림 영역: `getOperatorList()` 의 이미지 그리기 명령과 변환 행렬로 이미지 bbox를 구해, 렌더된 페이지 캔버스에서 잘라 낸다. 벡터 도형·차트처럼 분리가 어려운 영역은 "텍스트가 없는 영역" 기준으로 잘라 그림으로 처리
- 슬라이드형(16:9 PPT에서 내보낸) PDF와 문서형(A4) PDF를 모두 처리할 것. 슬라이드형은 "슬라이드 1장 = 1개 소절" 경향을 활용

**② 구조화 — 블록 모델**
아래 형태의 JSON을 기준 데이터로 쓴다 (필요하면 확장).
```json
{
  "book": { "title": "", "subtitle": "", "org": "", "theme": "academic", "trim": "188x257" },
  "chapters": [
    {
      "no": 1, "title": "", "accent": "#1F5FAF",
      "objectives": ["학습목표…"], "keywords": ["핵심어…"],
      "blocks": [
        { "type": "h1|h2|h3", "text": "" },
        { "type": "p", "text": "", "inline": [{ "range": [0, 4], "style": "bold|term" }] },
        { "type": "list", "ordered": false, "items": [""] },
        { "type": "box", "kind": "concept|example|tip|caution|note|definition|summary|think", "title": "", "blocks": [] },
        { "type": "figure", "src": "media-id", "caption": "", "no": "1-3", "size": "full|half|margin" },
        { "type": "table", "rows": [[""]], "caption": "", "header": true },
        { "type": "quiz", "items": [{ "q": "", "choices": [""], "answer": "" }] }
      ]
    }
  ]
}
```
- 기본은 **규칙 기반 추정**(글자 크기 순위·굵기·위치·번호 패턴 "1.", "①", "Ⅰ" 등·PDF 책갈피)으로 만든다
- 자동 추정은 틀릴 수 있으므로 ③ 편집기에서 사람이 고칠 수 있어야 한다

**③ 교정 편집기 (변환기 안의 새 화면)**
- 왼쪽: 블록 목록(드래그 순서 변경, 블록 유형 변경, 박스로 묶기/풀기, 챕터 나누기, 삭제·병합)
- 오른쪽: 실시간 조판 미리보기(펼침면)
- 그림 영역 다시 자르기, 캡션 입력, 학습목표·핵심어 입력, 테마·판형 선택
- 편집 내용은 저장 시 블록 JSON으로 함께 보관하여 **나중에 다시 열어 수정**할 수 있게 할 것

**④ 조판 엔진** — 3장 디자인 시스템을 CSS로 구현. 페이지 템플릿 자동 선택
**⑤ 페이지 분할** — 판형 기준으로 흘려 넣고 자동 분할(Paged.js 같은 CSS Paged Media 방식 또는 자체 측정 분할). 표·그림·박스가 페이지 경계에서 어색하게 잘리지 않게 처리
**⑥ 출력** — 기존 플립북 뷰어에 **HTML 페이지(텍스트 레이어가 아닌 실제 조판 텍스트)** 로 담아 선택·검색·확대가 선명할 것. 인쇄(브라우저 PDF 저장) 시 판형·여백 그대로 출력

### 3. 교재 디자인 시스템 (최소 요구 사양)

**판형·그리드**
- 기본 판형: **188×257mm (4×6배판, 대학 교재 표준)**. 대안 182×257mm(B5)
- 여백: 위 20 / 아래 22 / 안쪽 20 / 바깥쪽 18mm 수준, 펼침면 기준 좌우 대칭(짝·홀 페이지 반전)
- 본문 1단 기본 + **바깥쪽 사이드 여백(30mm 내외)** 을 두어 용어 설명·참고·아이콘을 배치(대학 교재 특유의 레이아웃). 2단 본문 템플릿도 제공
- 기준선 그리드(baseline grid)에 맞춰 본문 행간을 일정하게 유지

**타이포그래피 (무료·상업 사용 가능 폰트만)**
- 본문: 본명조(Noto Serif KR) 또는 Pretendard 중 테마별 선택, 9.5~10pt / 행간 170% 내외
- 제목: Pretendard 굵은 계열, 장 제목 > 절 제목 > 소절 제목 크기 체계(모듈러 스케일)
- 한국어 조판 규칙: `word-break: keep-all`, 양끝 맞춤 시 어색한 자간 금지, 문장부호 행두 금칙, 고아·과부 줄 방지(orphans/widows), 제목이 페이지 맨 아래에 홀로 남지 않게
- 숫자·영문은 본문 폰트와 어울리는 대체 폰트 지정

**색 체계**
- 테마 기본색 1개 + 챕터별 포인트 색(챕터마다 순환) + 회색 단계. 인쇄 고려해 과도한 원색·검정 덩어리 금지
- 박스 종류별 고유 색·아이콘 (개념=파랑, 예제=초록, 주의=주황/빨강 계열, 팁=노랑 계열 등, 테마에 맞춰 조정)

**필수 페이지 템플릿**
1. 표지 (책 제목·부제·기관명, 그래픽 기반 — 사진 불필요)
2. 목차 (자동 생성, 장·절·쪽번호, 점선 리더)
3. **챕터 표지(도비라)**: 큰 장 번호, 장 제목, 학습목표, 핵심어, 챕터 색 그래픽 — **챕터마다 색·그래픽이 달라질 것**
4. 본문 일반 (러닝헤드: 짝수 쪽 책 제목 / 홀수 쪽 장 제목, 바깥쪽 쪽번호)
5. 그림·표 중심 페이지 (전폭 그림, 그림 2개 배치 등)
6. 챕터 마무리 (핵심 요약 박스, 확인 문제)
7. (선택) 부록·색인

**필수 요소 컴포넌트**
- 장·절·소절 제목 (번호 체계 "1.2.3" 자동)
- 박스류 8종: 핵심 개념 / 예제 / TIP / 주의 / 참고 / 용어 정의 / 생각해 보기 / 정리
- 그림 캡션 (그림 1-3 자동 번호), 표 캡션 (표 2-1), 출처 표기
- 표 스타일 (헤더 행, 줄무늬 선택, 숫자 열 오른쪽 정렬, 페이지 넘김 시 헤더 반복)
- 목록 (불릿·번호·원문자 단계별 모양)
- 사이드 노트 (바깥 여백), 각주
- 강조 표기 (핵심어 굵게+색, 용어 첫 등장 표시)

**테마 3종 (시안 단계에서 비교)**
- `academic` 학술 클래식: 본명조 본문, 차분한 남색·회색
- `modern` 모던 테크: Pretendard 본문, 선명한 포인트 색, 기하 도형 그래픽
- `health` 보건·의료: 부드러운 청록 계열, 둥근 박스 (예: 치과위생사협회 교안용)

**품질 기준**: 한빛아카데미·생능출판 등 시판 대학 교재의 **편집 수준**을 목표로 한다(스타일 참고만, 특정 책의 디자인을 그대로 베끼지 말 것). 박스·표·도형 안 텍스트는 위치·줄간격·줄바꿈까지 맞아떨어져 **튀어나오거나 어색하게 줄바꿈되는 곳이 없어야** 한다.

### 4. 기술 제약

- Vercel 무료 플랜, GitHub 없음, 기존 저장·삭제·이력 구조 재사용. 무거운 처리는 **브라우저에서** 수행
- 출력 HTML은 지금처럼 **단독 실행**(외부 서버 없이 열림)을 원칙으로 한다. 폰트는 서브셋 WOFF2 임베드 또는 CDN 로드 중 장단점을 비교해 제안할 것(용량 vs 단독 실행)
- 교안 1개 저장 용량 한도(서버 설정 한도) 안에 들어와야 함 → 이미지 압축·폰트 서브셋 필요
- 새 코드는 `textbook.js` / `textbook.css` 처럼 **별도 파일**로 만들고 로더에서 불러올 것. 원본 조각(p/*.txt) 수정 금지
- 크롬·엣지 최신 기준, 모바일에서는 플립북 열람이 깨지지 않을 것
- 비밀번호·토큰을 직접 입력하거나 코드·문서에 적지 말 것

### 5. 진행 순서와 승인 단계

1. **분석 보고** — app.txt 구조, deck 데이터, 출력 생성 함수, 끼워 넣을 지점을 정리해 보고 (코드 수정 전)
2. **디자인 시안 (승인 게이트)** — 실제 교안 샘플로 **정적 HTML 시안**을 만든다: 표지 / 목차 / 챕터 표지 2종 / 본문 3종 / 챕터 마무리 × 테마 3종. 펼침면 스크린샷으로 보여 주고 **사용자 승인 후** 다음 단계 진행
3. **추출·구조화 엔진** — 샘플 PDF 3종(슬라이드형 2, 문서형 1)에서 블록 JSON 정확도 확인
4. **조판 엔진 + 페이지 분할**
5. **교정 편집기**
6. **변환기 통합** — 출력 형식 선택지 추가, 웹 저장·삭제 코드·이력과 연결, 블록 JSON 재편집
7. **배포·검증·사용설명서 갱신** — 각 단계 끝마다 배포 후 sha 대조, 실제 사이트에서 저장→열람까지 확인

각 단계가 끝나면 무엇을 했고 무엇이 남았는지 짧게 보고하고, 스크린샷을 함께 보여 줄 것.

### 6. 시작 전에 사용자에게 확인할 것 (권장안 함께 제시)

1. 기본 판형: 188×257mm(권장) / 182×257mm
2. 우선 적용할 테마 1개 (시안 비교 후 결정)
3. 구조화 방식: 규칙 기반 + 수동 교정(권장, 추가 비용 없음) / AI 자동 구조화 추가(Claude API 키를 Vercel 환경변수에 등록, 사용량만큼 비용 발생)
4. 폰트 방식: 임베드(단독 실행, 용량 증가) / CDN(가벼움, 인터넷 필요)
5. 인쇄용 PDF 출력이 필요한지, InDesign 원본 파일(IDML) 내보내기가 필요한지 (IDML은 1차 범위 밖으로 권장)

### 7. 완료 기준 (검수 체크리스트)
